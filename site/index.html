How it works

Your computer never accepts incoming connections, so it works behind NAT, Wi-Fi and firewalls.

  1. The client opens one encrypted connection out to the PublicLocal server.
  2. The server gives you a random HTTPS address with a valid certificate.
  3. Requests to that address travel down the connection to your local port. WebSockets and streaming work too.

Keep links for a week

Links last 24 hours. Sign in with GitHub and they last 7 days, and you can extend them again before they run out.

$ publiclocal login
$ publiclocal http 3000
Forwarding https://k7xq2m.publiclocal.app -> localhost:3000
Link expires in 7 days
$ publiclocal extend k7xq2m
$ publiclocal links

The free server is for temporary use

  • Links use random names and last 24 hours, keeping the same address if your connection drops. Sign in with GitHub for 7-day links you can extend.
  • Visitors in a browser see a short notice before your app. Webhooks, APIs and curl skip it, and you can skip it with the header PublicLocal-Skip-Warning: 1.
  • HTTP only, with fair-use limits on requests and traffic. See fair use.
  • Need a permanent address, your own domain, or TCP (SSH, databases)? Run your own server.

Run your own server

Your domain, no limits, TCP tunnels, automatic HTTPS. Any $5 VPS works.

# on the server (DNS: example.com and *.example.com point here)
publiclocal server --domain example.com --tokens "$(openssl rand -hex 24)"

# on your laptop
PUBLICLOCAL_SERVER=example.com PUBLICLOCAL_TOKEN=... publiclocal http --subdomain myapp 3000
Forwarding https://myapp.example.com -> 127.0.0.1:3000
