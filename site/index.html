What it is

A reverse tunnel you can use for free or run yourself

PublicLocal is an open-source reverse tunnel. It connects your computer to a public server over one encrypted connection and gives you an https:// address that forwards to a local port. It does what ngrok does, with two differences: the whole thing is open source, and you can run the server on your own domain.

Webhooks

Point Stripe, GitHub, Slack or Twilio at your laptop and watch callbacks arrive while you debug.

Demos

Send a client or teammate a link to the work in progress. Nothing to deploy, nothing to clean up.

Mobile testing

Open your local site on a real phone over HTTPS, so service workers, cameras and geolocation work.

OAuth callbacks

Use a real HTTPS redirect URL while building sign-in with Google, GitHub or Auth0.

Install

Start in seconds, with or without an install

Use plain SSH with nothing to install, or get the client for every feature. Works on Linux, macOS, Windows and FreeBSD.

ssh -p 443 -R0:localhost:3000 publiclocal.app

Nothing to download: any SSH client works. The link and a live request feed appear in the SSH window; Ctrl+C ends it. Install the client for passwords, the inspector and lasting links.

curl -fsSL https://publiclocal.app/install.sh | sh

Downloads the right build, verifies its checksum and installs to /usr/local/bin.

irm https://publiclocal.app/install.ps1 | iex

Run in PowerShell. Installs to your user profile and adds it to PATH; no admin rights needed.

docker run --rm --network host ghcr.io/sevenoways/publiclocal http 3000

Images for amd64 and arm64 on GitHub Container Registry.

go install github.com/sevenoways/publiclocal/cmd/publiclocal@latest

Builds from source with Go 1.27 or newer.

How it works

Your computer never accepts incoming connections

That is why it works behind NAT, hotel Wi-Fi and corporate firewalls without any router changes.

  1. The client dials the serverOne encrypted connection, kept open and multiplexed. Nothing listens on your machine.
  2. You get a random HTTPS addressWith a valid certificate, ready to share. It stays the same if your connection drops.
  3. Requests flow down the tunnelEach visitor request is forwarded to your local port. WebSockets, streaming and large uploads work.

The small things

Built by someone who shares localhost every day

Little features that save a trip to a dashboard, a password manager, or your phone's keyboard.

Request feed and inspector

Every request shows in your terminal as it happens, and the inspector at localhost:4040 shows headers and bodies and replays webhooks against your app while you fix the handler.

Only for people you choose

--allow-github anna,@acme makes visitors sign in with GitHub; only the people or organisation members you name get through. Free.

Webhook inbox

publiclocal catch records every request with nothing running locally. Write the handler tomorrow, then publiclocal replay --to 3000.

Feedback from the people you share with

--feedback adds a comment button to your pages; what visitors write shows up in your terminal. --live lets teammates watch requests arrive.

Webhook signatures checked

--verify stripe:whsec_... marks every webhook valid or not, for Stripe, GitHub, Slack and Shopify. Find out at once if it's the secret or your code.

Mocks and bad networks

--mock /api/users=users.json answers from a file before the backend exists. --latency 2s --fail 10% tests the slow, flaky path.

Share a folder or a file

publiclocal share ./build serves a folder, publiclocal share report.pdf one file. No web server needed.

Self-destructing links

--max-visits 1 lets exactly one person in; --expires 30m ends the link on time. A --note tells visitors what they're looking at.

Password-protected links

--password makes the server ask visitors for a password before anything reaches your app. Free server included.

QR code in the terminal

--qr prints a code to scan with your phone, so testing on a real device takes one glance instead of typing a random name.

Links that explain themselves

An offline or expired link shows visitors when it was live and how busy it was, and every link answers /.publiclocal/status with JSON.

Two ways to use it

Start on the free server, move to your own when you want

Same binary, same commands. Your own server adds your domain, fixed names, TCP and no limits.

Free public server

For quick tests, demos and webhooks.

  • No account. Links last 24 hours, or 7 days with GitHub sign-in, extendable
  • Random names like k7xq2m.publiclocal.app
  • HTTP and HTTPS; visitors in a browser see a short notice first
  • Fair-use limits on requests and traffic
$ publiclocal http 3000
$ publiclocal login      # 7-day links
$ publiclocal extend k7xq2m

Your own server

For your domain, permanent links, TCP and teams. Any $5 VPS.

  • Addresses like https://myapp.example.com, no expiry
  • Automatic Let's Encrypt certificates, or one wildcard certificate
  • TCP tunnels: SSH, Postgres, MySQL, Redis, game servers
  • Token authentication, your own limits
# server (DNS: example.com and *.example.com)
publiclocal server --domain example.com --tokens "$(openssl rand -hex 24)"
# laptop
publiclocal http --server example.com --subdomain myapp 3000
Forwarding https://myapp.example.com → localhost:3000

AI assistants

Works with Claude Code, Cursor, VS Code, Codex and Gemini CLI

PublicLocal includes an MCP server. Ask your assistant to "share my dev server on port 3000" and it opens the tunnel and hands you the link. Tunnels close when the session ends, and --allow-ports limits what it may expose.

claude mcp add publiclocal -- publiclocal mcp
codex mcp add publiclocal -- publiclocal mcp

FAQ

Questions people ask

What is PublicLocal?

PublicLocal is an open-source reverse tunnel. It makes a web server running on your own computer reachable from the internet at a public HTTPS address, so you can test webhooks, show work in progress or open your dev server on a phone. One command gives you a link on the free server at publiclocal.app, or you can run the same software on your own server and domain.

Is PublicLocal a free alternative to ngrok?

Yes. It is MIT-licensed and free to use. The hosted server needs no account; links last 24 hours, or 7 days if you sign in with GitHub. Unlike ngrok, both the client and the server are open source, so you can also self-host it on your own domain with no limits.

Can I use it without installing anything?

Yes. With any SSH client run ssh -p 443 -R0:localhost:3000 publiclocal.app (change 3000 to your app's port). The public HTTPS link and a live request feed appear in the SSH window, and Ctrl+C ends the tunnel. Install the client for passwords, the inspector, file sharing and links that survive restarts.

How do I expose localhost to the internet?

Install PublicLocal, then run publiclocal http 3000 (replace 3000 with your app's port). It prints a public https:// link that forwards to your local app. Press Ctrl+C to stop sharing.

Does it work behind NAT, firewalls or CGNAT?

Yes. The client makes a single outbound encrypted connection to the server, and all traffic flows back through it. Your computer never accepts incoming connections, so no port forwarding or router changes are needed.

Can I use my own domain?

Yes, by running your own server. Point a domain and its wildcard DNS record at any small VPS, run publiclocal server --domain yourdomain.com, and your tunnels get addresses like https://myapp.yourdomain.com with automatic Let's Encrypt certificates.

Does it support TCP, SSH or databases?

TCP tunnels (SSH, Postgres, MySQL, Redis, game servers) are supported on self-hosted servers with publiclocal tcp 22. The free public server is HTTP and HTTPS only.

Is it safe to share links from the free server?

Traffic between your computer and the server is encrypted, and visitors reach your link over HTTPS. Because anyone can create a link, browsers first see a short notice saying the page is a temporary developer tunnel, and links use random names so they cannot imitate brands. Webhooks, APIs and curl skip the notice. Report misuse to abuse@publiclocal.app.

Can I limit a link to specific people?

Yes. publiclocal http --allow-github anna,@acme 3000 makes visitors sign in with GitHub, and only the users or organisation members you name get through. --allow-ip limits by network instead, and --password adds a shared password.

Can I receive webhooks before my app is ready?

Yes. publiclocal catch gives you a link that answers and records every request even with nothing running locally. Once your handler exists, publiclocal replay --to 3000 sends the saved requests to it.

Can I replay a webhook?

Yes. While a tunnel runs, the inspector at localhost:4040 lists every request with headers and body. Select one and click "Replay against localhost" to send it to your app again, as often as you need, without triggering the webhook at the source.

Can I share a folder or a file without a web server?

Yes. publiclocal share ./build serves a folder (with a listing, or as a site if it has an index.html) and publiclocal share report.pdf serves one file. All link options apply, so --password and --max-visits 1 hand one file to one person.

Can I password-protect a link?

Yes. publiclocal http --password s3cret 3000 makes the server ask visitors for the password (any user name) before anything reaches your app, on the free server too. Your app never sees the password header.

Can AI coding assistants use it?

Yes. PublicLocal includes an MCP server. After claude mcp add publiclocal -- publiclocal mcp (or the equivalent in Cursor, VS Code, Codex CLI or Gemini CLI) you can ask the assistant to share your dev server and it opens the tunnel and gives you the link.
